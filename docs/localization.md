# Localization

UnitFlow ships English first while keeping user-facing Flutter strings in generated localization resources so additional locales can be added without rewriting presentation code.

## Files

- `apps/unitflow_app/lib/l10n/app_en.arb` is the English template catalog.
- `apps/unitflow_app/l10n.yaml` configures Flutter localization generation.
- `apps/unitflow_app/lib/l10n/generated/` is generated by Flutter tooling and is not hand-edited.
- `UnitFlowApp` uses the generated delegates and supported-locale list.

## Generate localizations

From `apps/unitflow_app`:

```bash
flutter pub get
flutter gen-l10n
```

CI and the release workflow run localization generation explicitly before analysis and tests.

## Adding a locale

1. Copy the English ARB structure to a locale-specific file such as `app_hi.arb`.
2. Set `@@locale` to the target locale.
3. Translate user-facing values while preserving message keys.
4. Preserve ICU placeholders and plural/select syntax exactly.
5. Run `flutter gen-l10n`.
6. Run `flutter analyze --fatal-infos --fatal-warnings` and `flutter test`.
7. Manually review layouts with long translated text, large text scaling, narrow mobile widths, and desktop navigation.

## Message design rules

- Do not concatenate translated sentence fragments where a complete parameterized message is practical.
- Use ICU plural/select messages for language-sensitive grammar.
- Keep stable unit IDs and conversion constants out of translation resources.
- Unit display names and category labels currently come from catalog/domain metadata; before adding non-English production locales, decide whether those domain labels will be localized through generated keys or a catalog-localization adapter.
- Error details intended only for logs must not be placed in user-facing localized messages.

## Generated-source policy

Generated localization Dart files are produced by the pinned Flutter toolchain during development and CI. Contributors should edit ARB files and `l10n.yaml`, not generated output.

## Translation quality

Machine-generated translations should not be treated as release-ready without human review. A locale should only be advertised as supported after its primary workflows, formatting, accessibility, and terminology have been reviewed on representative screen sizes.
